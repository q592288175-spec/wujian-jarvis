1. 打开项目 `.runtime\desktop-build\小木-win32-x64\小木.exe`，核对顶部账户、实际余额和行情日期。
2. 收盘完整数据可取得后，在火页点“刷新盘后数据”。展开“六所数据覆盖”，区分同日行情、临时快照、无成交、技术不足与缺映射。当前正式观察范围仍为配置87品种。
3. 标签栏右侧的“三组多强空弱”按本人2026-10-19最新选择，始终使用日K顺势池。红字是多头，绿字是空头；点击看5/20日延续、逆向回撤、相关性及替换原因。同板块可以入选，同方向高度相关者只保留龙头；其他模式页仍显示同一日K组合，不随标签误换来源。
4. 水研究完成后，报告独立保存。“核对并应用草稿”按字段选择，默认不勾选；需要时可选全部差异。替换前的本人记录保留在交易卡时间线。研究失败、重复启动和迟到结果不自动覆盖本人四问。
5. 金填写计划并按原流程确认交给土，土记录真实执行，木按已登记事实复盘。比较、AI报告和提醒不产生已批准计划。
6. 账户初始资金须按真实记录补齐。余额同步与交易实际盈亏分开；入出金和校准产生的余额变化不能直接当作交易业绩。
7. 有重要新增记录后，在“账户与规则 → 自用备份与恢复”点“创建完整恢复点”，等待“备份与哈希校验完成”。备份期间研究/业务写入暂缓，原表单保留。

## 三组比较的口径

- 来源改为现有日K顺势池：日MA10方向、今日高低点和双严格1万手，原四模式筛选不变。
- 使用同一具体合约、同一截止日的日线，至少21根共同交易日收盘计算20日持续性。近5日与20日均同向才列持续龙头；其余仍在详情列为备选，不改变火原入池结果。
- 方向内按5/20日波动调整收益、20日顺向效率、20日抗逆向回撤四项百分位等权排序。多头找涨得持续、回撤较小的候选；空头反向。具体公式及本次结果见[日K龙头与风险去重](relative-strength-leaders-2026-10-19.md)。
- 不设“一大板块只能一个”。同方向国债各期限、原油燃料链等同风险族只留排名靠前者；20或60日共同收盘收益相关达到0.80则递补；近期相关未知不当作低相关。每天目标3多3空，不足保留空位。
- 参数是本工作台的观察比较方法，未经收益回测，不是作者原规则或胜率，不因龙头排名自动加仓。多空配对优先价格正相关，但三多三空不等于风险中性；详情保留全部相关关系，手数、共同驱动、点值、止损与账户预算仍需核验。
- 每个输入快照独立保存于 `.runtime\relative-strength`，包括版本、合约映射、数据哈希与排除原因。行情刷新完成后重算；同一输入复用结果，不覆盖历史组合。

## 备份是什么

“完整恢复点”是本人自用私密包，包含源码、依赖、现行资料包、行情、研究、业务数据库、通知库和本机配置。不要当作分享包发送。

备份在 `.runtime\checkpoints\final-*`。`manifest.json` 必须是 `status: complete`；`verification.json` 表示逐文件校验，`restore-verification.json` 表示已在隔离目录复制并复核。复制中的目录和仅有文件夹名称都不代表可恢复。

SQLite使用一致性备份接口，不直接复制正在写入的WAL文件。各数据库独立取快照；不要在备份期间人工编辑项目源码或外部资料。外部模型、免费网页行情和飞书政策仍可能变化。Windows用户加密的凭据换电脑后可能需要重新配置。

桌面包的ASAR按实际文件复制和校验，使用Electron的`original-fs`避免被当作虚拟目录。依据：[Electron ASAR原始文件读取说明](https://www.electronjs.org/docs/latest/tutorial/asar-archives#treating-an-asar-archive-as-a-normal-file)。本次真实点击备份时发现并修复该问题；之前中断的目录保留“未完成”状态，不用来恢复。

开工前恢复点：`.runtime\checkpoints\final-2026-10-16T03-52-28-316Z`，25,801文件、4个SQLite库，已恢复至 `output\final-release\restore-rehearsal-before` 并通过哈希/表级核对。

## 如何恢复

1. 先停止交易记录录入、研究和行情刷新，正常退出小木；确认本机4318服务已停止。保留当前整个项目及 `.runtime`，不要先删除损坏目录，也不要把新记录覆盖回旧备份。
2. 优先在当前项目中运行下列隔离演练命令。目标必须是新的空目录；脚本拒绝覆盖已有目标，拒绝越出项目output。

```powershell
node scripts/system-backup.mjs verify '.runtime/checkpoints/这里填恢复点目录名' 'output/restore-check-new'
```

3. 查看生成的 `restore-verification.json` 是否 `ok:true`，同时核对需要的账户、交易卡、余额和最近操作日期。备份后的新增记录不能凭空恢复，必要时从保留的当前库专门对账迁移。
4. 恢复包中的 `project` 对应项目根目录，`materials` 对应同级 `资料包`。正式切换时先可恢复归档原项目和原资料包，再将验证副本放回原D盘路径。不要往旧目录零散覆盖SQLite和WAL，也不要用Git重置数据。
5. 桌面构建内记录项目路径。回到原路径可直接打开APP；换路径需在新目录运行 `node scripts/build-desktop.mjs` 后使用新EXE。切换Windows用户需重新配置受用户加密保护的凭据。外部十月交易参考原件仍在原资料目录，知识库保留已索引正文；不把恢复操作扩展成删除外部资料。
6. 先确认账户、历史、数据日期，再恢复提醒。停机期间不会补猜行情、委托或成交。不要同时启动新旧两套工作台写同一数据。
