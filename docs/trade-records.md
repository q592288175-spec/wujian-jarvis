# 小木实际执行、资金与复盘记录

启用日期：2026-10-03。只修改十月小木项目，不改资料包里的交易规则，不连接券商下单。

## 每笔交易

1. 金冻结并人工批准计划。土的开多或开空继承该计划方向；记录平仓时自动对应平多或平空，不随后来行情反转改写历史方向。
2. 土记录实际成交时间、均价、手数、止损保护价、保护与异常说明。输入时自动保存草稿；点击保存执行记录后才确认成交。
3. 平仓填写退出原因和实际净盈亏：盈利填正数，亏损填负数，保本填0。该金额已包含成本，不再扣一次手续费。
4. 确认平仓后，账户新金额 = 入账前金额 + 本次实际净盈亏。部分平仓只更新本次数量和金额，剩余持仓保留。下一张金计划自动使用账户新金额计算手数。
5. 木自动展示本笔已实现净盈亏、剩余手数、入账前后金额和当前账户金额；只写“哪些做得好、哪些做得不好、下次注意什么”，停顿后自动保存。旧版复盘保留。

实际盈亏填错时，展开“更正已入账盈亏”，填写正确的总金额和原因。系统只将差额计入账户，保留原成交及每次更正。重复提交相同记录不重复计账。

账户金额仍可人工对账。入金、出金或其他软件交易造成差额时，在账户快照校准；校准留资金流水，不伪装成某笔交易的盈亏。无真实余额时不猜100万元或10万元。

数据库仍为 `.runtime/five-workbench.sqlite`，行情库独立。首次启用只登记现有余额为接入余额，不重造旧盈亏。生成文件是数据库的副本，不应直接修改；后续同步会按数据库重建。

业务保存后同步文件，启动时也重建；失败时不丢数据库，页面显示失败原因，服务每15秒重试。输入尚未发到服务端时，浏览器本机草稿保留，下次打开同张卡恢复。恢复备份时须先关闭APP并保留原数据库及WAL，不用运行中的文件副本替换。

## 盘后核验边界

- 只根据持仓后已取得的完成日线提供参考浮盈亏、是否触及保护价和行情日期。
- 入场或调整保护当天，日线不能判断先后；缺失、未完成或过旧的数据保持明确提示。
- 止损触及不等于成交，参考浮盈亏不进账户；只有本人确认的实际净盈亏入账。
- 旧CSV成交保留历史记录，未核对前不自动推导持仓和资金，避免重复计入。
- 本记录系统不是交易软件实时余额连接，也不会自动下单。新规则仍须人工确认，AI只分析已经记录的事实。

## 复盘交给AI

直接提供 `小木操作记录.md`；需要统计时同时读取 `全部记录.json` 与 `账户资金流水.csv`。按账户、交易轮次、计划版本区分，实盘、模拟、影子分别统计；草稿不算成交，资金校准不算交易收益，盈亏更正仅按差额累计。缺失的记录不能凭推断补成实盘事实。

验收：`node --test tests/trade-records.test.mjs`；隔离界面流程 `node scripts/verify-trade-records-ui.mjs`。测试数据仅写在 `.runtime/test-trade*`，不写正式业务库。
