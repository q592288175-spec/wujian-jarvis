## 使用与保存

1. 收盘后刷新盘后数据，确认日期、正式行情覆盖与缺口。
2. 选择需要的周期，点击“盘后数据复盘”。有旧数据时自动调用原刷新流程；正在刷新时等待完成后再点击。
3. 先显示已经保存的计算表，再显示AI解读。进度中禁止重复点击；失败可重新复盘，历史仍保留。
4. 弹窗顶部可切换历史；同一天重做会生成独立记录，不覆盖此前结果。关闭窗口不取消后台任务，再次点击会接续正在进行的任务。

每次输出在 `.runtime/postmarket-reviews/<任务ID>/`：

| 文件 | 用途 |
|---|---|
| `input.json` | 固定的扫描、交易日历、87品种具体主力映射和保存的日K原值；含来源、刷新时间、临时标识 |
| `result.json` | 全部计算、反证、下一日条件、数据缺口、AI状态及输入哈希 |
| `status.json` | 进度、完成/有缺口/失败状态；重启中断明确提示重做 |
| `复盘报告.md` | 可供Codex或其他模型读取的中文复盘报告 |

界面刷新与输入固定时间精确到分钟，使用北京时间。报告中的日K已收盘与动态周/月K分开标注。

## 可核验口径

| 项目 | 程序计算与边界 |
|---|---|
| 当日涨跌 | 当日收盘÷同一具体合约上一交易日收盘－1；不用结算、昨结算或旧主力价格 |
| 近5日 | 当日收盘÷5个交易日前收盘－1；要求6根完整可核验日K，节假日按现有AKShare交易日历 |
| 量比 | 当日成交量÷前5个交易日成交均量；缺失或均量为零不编造比值 |
| 持仓变化 | 同合约当日持仓－上一交易日持仓；不等于资金净流入，不证明主力方向 |
| 收盘位置 | （收盘－最低）÷（最高－最低）；全天无价差显示不足 |
| 板块相对 | 品种当日涨跌－同板块有效样本等权涨跌；含本品种，至少2个有效样本 |
| 商品背景 | 配置品种中有效的具体主力昨收涨跌等权，股指与国债排除；列明样本数与代码，不称全市场指数 |
| 事件催化 | 本功能未新增新闻搜集。无可靠事件证据时写“原因待核验”，AI不得补造新闻或政策因果 |

复盘判断是独立的当日表现提示，不是新筛选规则：收盘在日MA10逆势侧，或当日逆势且突破前日保护极值，提示“出现转弱迹象”；顺观察方向收盘且位于当日顺势半区，提示“顺势推进”；逆势但未触及上述转弱条件，提示“正常回撤”；其余为“整理”。数据或日MA10不足显示“数据待核验”。这不代表月周趋势已反转，也不从单日涨跌推出胜率。

反证同时检查近5日表现、板块相对、前日极值和持仓减少。总览的延续观察对象要求顺势推进、近5日同向且板块相对同向；按相对表现最多展示每侧3个，不凑数量、不创造评分，完整表保持扫描原顺序。次日条件只使用已经保存的当日高低点和日MA10，供观察，不是入场触发或下单价。

历史比较只接受上一交易日、同周期、同扫描版本、同复盘口径的已保存结果。当前首次启用无10月8日底稿，明确无法比较新增、退出、改善和转弱；不会根据今天的数据伪造昨天的判断。

## 输入与并发保护

- 以既有 `latestFire`、`startFireRefresh` 和具体合约缓存为入口，不修改扫描规则或资料包。
- 核验交易日、来源、合约、OHLC范围、临时快照、当日扫描与保存日K数值是否一致。郑商所三位年码沿用现有映射还原，不将等价代码误判为换月。
- 换月用新具体主力自己的前值；缺前值则标缺口，不能借旧主力拼涨跌。未来日K不进入本次输入。
- 取数前后扫描哈希必须一致。固定输入期间拒绝新的页面刷新；后台扫描变化导致本次失败，绝不混合名单。输入保存后AI只读副本。
- 同时仅一个复盘任务；重复请求返回同一任务。刷新失败保留旧缓存，但不能输出当日成功报告。
- AI未配置时保留真实计算并明确未执行AI；AI失败不丢计算，报告显示有缺口。窗口关闭后的迟到响应不改写其他窗口内容。
