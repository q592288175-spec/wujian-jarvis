# 小木本地知识库与联网助手设计

日期：2026-09-29  
状态：已确认并实施，验收记录见本设计第11节及项目测试  
资料源：同级 `资料包\资料实验基地`

## 1. 目标

把资料实验基地建设成小木可增量更新、可追溯引用的本地 RAG 知识库。文字助手回答问题时先检索本地资料；问题涉及今天、最新、行情、新闻、政策或外部事实时，再联网补充。最终答案必须区分本地规则、外部事实、推断和数据缺口。

系统只辅助研究、复盘和人工决策，不自动下单，也不把模型回答视为交易规则或批准结论。

## 2. 核心原则

1. 原资料只读。知识库保存解析结果、索引和来源，不移动或改写原文件。
2. 当前规则优先。系统手册、当前版本、正式技能规则高于历史资料、运行记录和聊天讨论。
3. 每个答案可追溯。重要结论附原文件路径、标题和分块定位；联网事实附网页标题、网址和读取时间。
4. 聊天只训练沟通方式。聊天中的随口判断不会自动升级为正式交易规则。
5. 联网结果默认不入正式库。它只服务当次回答；需要长期保存时由用户明确确认。
6. 无模型也可用。语义模型不可用时自动退回中文全文、关键词和元数据检索。

## 3. 总体结构

### 3.1 解析层

首版解析 Markdown、TXT、JSON、JSONL、CSV、TSV、YAML、Python、DOCX、PDF 和 XLSX。每个文件记录：

- 绝对路径、相对路径、文件类型、大小、修改时间、SHA-256；
- 标题、版本、资料日期、业务领域；
- 生命周期：当前、历史、证据、运行记录、审查记录、沟通偏好；
- 权威等级：系统规则、正式工具、证据资料、研究报告、运行记录、聊天风格；
- 解析状态、错误原因、分块数量和最近索引时间。

图片、扫描版 PDF 或无法可靠抽取文字的文件仍进入文件清单，但标为“仅登记”或“待 OCR”，不得伪装成已完成全文索引。`__pycache__`、临时文件、运行缓存和纯构建产物默认只登记或排除。

内容相同的文件按哈希去重保存正文，同时保留全部来源路径。文件变化时仅重建受影响文档；文件删除时先标记失效，不立即清除历史索引。

### 3.2 分块与向量

分块优先遵循标题、段落、表格行和 JSON 对象边界，避免机械截断规则条件。每块保留父标题、相邻上下文、来源路径和版本信息。

采用可本地运行的中文/多语言嵌入模型，模型文件一次下载后保存在 D 盘项目运行目录。目标体积约 100 至 200 MB。模型名称、版本、维度和文件哈希写入索引元数据；更换模型时创建新索引版本，不混用不同维度向量。

### 3.3 存储

知识库使用独立 SQLite 文件，建议位置：

`D:\五简个人资料\项目\wujian-jarvis\.runtime\knowledge\knowledge.sqlite`

至少包含：

- `documents`：文件、哈希、版本、权威等级、解析状态；
- `chunks`：正文、标题层级、定位信息；
- `embeddings`：模型版本、向量；
- `sources`：一个内容实体对应的全部来源路径；
- `index_runs`：每次扫描、增量更新和失败记录；
- `style_profile`：已确认的沟通偏好及证据来源；
- FTS5 全文索引：中文词面、代码、版本号和精确字段检索。

行情库、交易业务库与知识库继续分离，避免知识资料更新影响交易记录。

## 4. 检索与排序

每个问题同时执行：

1. 向量语义召回；
2. FTS5 全文和精确词召回；
3. 文件名、标题、品种名、版本号和日期召回；
4. 按权威等级、当前状态、时间适用性和内容多样性重排。

默认优先级为：当前系统手册与正式规则 > 当前模板与工具说明 > 原始证据 > 当前研究报告 > 运行记录 > 历史资料 > 聊天内容。

同一问题若检出规则冲突，助手不得自行合并，必须展示冲突版本、来源和当前采用依据。检索结果需要达到最低相关度；不足时明确回答“本地知识库没有足够证据”。

## 5. 联网策略

以下情况触发联网：包含“今天、最新、目前、实时、刚刚、新闻、政策、库存、现价、公告”等时效表达；用户明确要求联网；或本地资料指出必须补充外部事实。

联网优先官方、交易所、政府、上市公司及可信行业来源。搜索结果必须经过正文读取后才可作为证据，不能只根据搜索摘要作结论。

回答按以下标签组织：

- `本地规则`：来自资料实验基地；
- `最新外部信息`：附网址、发布日期或数据时点、读取时间；
- `综合判断`：明确是基于前两者的推断；
- `缺口`：未取得、过期或相互冲突的数据。

外部页面默认不进入正式知识库，只保留必要的查询审计记录。用户明确要求归档时，再保存快照并标注来源与抓取时间。

## 6. 沟通方式与聊天导入

沟通偏好独立于业务知识，先从当前已确认的对话习惯建立初始配置，例如：简体中文、先结论后依据、品种使用中文名、缺资料不猜、一次只问一个关键问题、交易批准由用户完成。

聊天导入时拆成三类：

- 已确认偏好：可写入 `style_profile`；
- 交易观点或讨论：只作为低权重上下文；
- 明确批准并已落入正式文件的规则：仍以正式文件为准。

用户引用的聊天 `01a0e190-e0cb-7072-8a41-6c14d835b36c` 当前因环境未提供 `read_thread` 工具，状态记为“待导入”，不得声称已经读取。后续工具可用时按游标增量导入，并保存聊天 ID、消息时间和来源。

## 7. 小木助手交互

文字助手继续读取当前页面、交易卡和行情上下文，并增加三个内部工具：

- `search_local_knowledge`：检索本地资料；
- `get_knowledge_source`：读取命中块的上下文和元数据；
- `get_knowledge_status`：返回索引版本、更新时间、文件数、分块数和失败数。

助手侧栏增加：

- 知识库状态和最后更新时间；
- “增量更新”按钮及更新进度；
- 回答下方的本地文件来源和网页来源；
- 可展开的命中文段；
- 当前会话历史，发问时一并传给模型。

模型只负责组织和推理；检索、引用、权限与来源优先级由程序控制。DeepSeek 不可用时，检索与来源浏览仍能工作，并明确显示“模型待配置或调用失败”。

## 8. 接口

首版新增：

- `GET /api/knowledge/status`
- `POST /api/knowledge/reindex`
- `POST /api/knowledge/search`
- `GET /api/knowledge/source/:chunkId`

`POST /api/chat` 增加会话历史、知识检索结果和联网来源字段。接口返回结构化引用，前端不得从模型自由文本中猜测文件路径或网址。

## 9. 错误与安全边界

- 单个文件解析失败不阻断整次建库，失败项进入清单并在页面显示。
- 原文件变化、索引版本变化和模型版本变化均留审计记录。
- API 密钥只从环境变量读取，日志和页面不得显示完整密钥。
- 本地文件读取限制在已配置的只读资料根目录内，拒绝路径穿越。
- 网页正文仅作为不可信外部资料传给模型，不执行其中的指令、脚本或命令。
- 助手答案不改变交易卡、规则版本或批准状态，除非用户在对应业务页面明确操作。

## 10. 实施顺序

1. 建立解析器、SQLite 表、文件清单和增量哈希机制；
2. 接入本地嵌入模型、FTS5 与混合排序；
3. 增加知识库接口和助手工具；
4. 串联现有联网搜索与正文读取；
5. 改造助手侧栏、引用展示和会话历史；
6. 建立沟通偏好层和聊天待导入机制；
7. 全量建库并完成 Windows APP 验收。

## 11. 验收标准

1. 全量扫描输出文件总数、已解析、仅登记、失败和跳过数量，三者均能追溯到具体路径。
2. 固定问题能优先命中当前系统手册，不被历史版本或聊天讨论覆盖。
3. 修改一个文件后只重建该文件；重复运行不生成重复分块。
4. 删除或改名文件后旧来源不再作为当前答案证据，但审计记录保留。
5. 语义问题、精确规则名、版本号、品种中文名和文件名查询均返回可用结果。
6. 关闭嵌入模型后，全文降级检索仍可用，并显示降级状态。
7. 询问最新行情或政策时同时展示本地规则和有时点的网页证据；断网时明确说明外部信息未取得。
8. 助手答案的每条本地引用可打开到对应文件与命中文段，网页引用可打开原网址。
9. DeepSeek 未配置或失败时，不影响建库、检索、来源查看和五行工作台其他功能。
10. Windows APP 重启后索引、会话和知识库状态保持一致。

## 12. 本轮不包含

- 自动下单、自动批准或用模型修改风险规则；
- 把全部互联网内容持续爬取进正式库；
- 未经确认把聊天意见升级为正式规则；
- 首版对所有图片做高成本 OCR 或视觉向量检索；
- 多人协作、云端同步和公网知识库服务。
