# 盘后刷新修复与验收

2026-10-12，Windows / OpenAI Codex。

## 使用变化

点击“刷新盘后数据”，按钮立即禁用并显示刷新中。后台先更新主力合约行情，再扫描配置中的全部87品种，最后更新月、周、日对应的筛选与环境数据。三个模式仍使用原有条件，成交量和持仓量均须严格大于1万手。

原“目标日期”位置改成“最后刷新 YYYY-MM-DD HH:mm”，采用北京时间；“数据 YYYY-MM-DD”继续表示行情交易日期。收盘前或休市时，刷新时间可以是今天，完整行情日期仍是上一交易日。失败也保留本次刷新时间和原因。

页面显示检查规则、更新主力行情、扫描全品种、更新结果和完成/失败。重复点击共用正在运行的任务。中断后重新打开会提示重试，不会永久显示刷新中。服务拒绝或请求失败时，按钮恢复并显示错误。

## 发现与修复

| 问题 | 最小修复 |
| --- | --- |
| 原按钮只调用火扫描，未等待主力行情刷新 | 串接现有refreshEod与扫描流程 |
| 请求被拒绝时没有捕获错误 | 即时按钮反馈、页面错误与失败重试 |
| “目标日期”不能说明是否刚刷新 | 独立持久化开始、完成、状态及行情日期 |
| 一个交易所主力映射失败会丢掉其他交易所已取得映射 | 各交易所分别采集；文华映射优先、人工映射最后覆盖的原次序保持 |
| 后端刷新状态仅在内存 | 原子保存.runtime/fire-refresh.json，重启保留结果并识别中断 |

本轮锁定规则核验仍在取数前和扫描前执行。行情缺口不伪装成功，失败保留现有扫描；不创建交易卡、计划或下单。
