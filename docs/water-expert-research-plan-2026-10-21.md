# 小木水分析：一键品种研究方案

日期：2026-10-21（北京时间）

状态：已完成现状核查与实施设计，尚未改程序、开通服务或进行新版报告验收。本文不是当日行情报告，不提供燃料油当前方向判断。

## 一、最终要交付什么

用户从火选择品种，进入水，点击“启动 AI 深度研究”。小木自行查资料、读取原文、核对数据、补查关键缺口，交付一份能快速读懂、可以追溯的品种研究报告。用户不必搜资料、整理链接或填表才能得到报告。

报告要回答：

1. 这个品种现在最重要的矛盾是什么，价格主要受什么推动？
2. 供给、需求、库存、成本、现货和期货之间，发生了什么变化？
3. 哪些因素支持上涨，哪些支持下跌，哪些已经被价格反映？
4. 未来几个交易日与未来几周，分别有哪些合理情景？
5. 小木目前倾向哪一种解释，依据是什么，什么会推翻它？
6. 用户若参考这一判断，应重点等待或观察什么，当前不适合贸然行动的原因是什么？

验收不是“成功输出长文”，而是用户能说清主线、反面证据、重要缺口和下一步观察条件，并能点开关键判断对应的原始依据。

这里的“全方位”指覆盖品种的重要定价因素并披露未知，不承诺穷尽所有因素，不承诺预测准确或提供有统计保证的胜率。所有研究建议与交易批准、账户风险和下单权限分开。

## 二、现有基础和真实缺口

本次检查的是当前十月项目源码、项目内燃料油框架，以及一份已保存的铁矿石研究报告。没有把历史报告中的行情数字当作已核实的当日事实。

| 已有实现 | 核查发现 | 应怎样改 |
| --- | --- | --- |
| 品种专属框架加载 | `research-agent.mjs` 会实际读取运行规范、定价模型和品种框架，不是完全没有框架 | 保留；把框架中的指标要求提前用于制定检索任务 |
| 并行采证 | `research-evidence.mjs` 采集近期新闻、仓单、席位、机构索引等，但调用入参没有专属指标清单 | 从“按品种搜几条新闻”升级为“按必查指标找证据” |
| 官方来源 | `official-sources.mjs` 主要读取公告列表、RSS 和有限正文片段，不等于接通完整的官方统计序列 | 对库存、产销、进口等建立具体原表或数据接口映射 |
| 自动补搜 | 提示词仅在某个大维度完全无证据时才准补搜，最多两次；有一条基本面新闻不代表库存和基差已查到 | 按关键指标缺口补查，不以“大类有内容”作为停止依据 |
| 报告写作 | 提示词要求正文 1800 字以内，偏重价格阶段与四维摘要；还要求部分缺数据时仍给阶段 | 速读与完整报告分层；允许“技术趋势已知，基本面判断不足” |
| 结果核验 | `research-audit.mjs` 主要检查章节和链接来源，不能验证每个数字与原文是否一致 | 加入证据引用、日期、单位、口径、计算和关键结论支持关系检查 |
| 页面 | `dist/workbench.js` 的水页以速读和本人四问表单为主，空白时展开多个文本框 | 改为报告优先；本人记录折叠保留，读报告不需填表 |
| 历史与人工记录 | 有独立研究任务、报告文件和草稿应用流程 | 全部保留，不自动覆盖人工判断、不改变原有批准状态 |

抽查的 2026-10-16 铁矿石旧报告已经会标明基差口径不齐、铁水数据缺失，说明已有有用基础。但“识别缺口”尚未形成稳定的“针对缺口找原表、再复核”流程。不能只通过换页面或加长提示词解决。

## 三、推荐路径

推荐在现有水研究中升级，不另建第二个研究系统，也不先更换整个模型栈。

```text
选择品种、具体合约与研究截止时点
        ↓
读取原有品种框架，生成必查指标和问题清单
        ↓
官方定点取数 + 搜索查找资料 + 已授权研报
        ↓
读取原文、表格或 PDF，记录时间、口径和出处
        ↓
逐项检查覆盖、冲突与时效，自动补查关键缺口
        ↓
形成事实表和可复算的价格、库存、价差历史
        ↓
比较多空解释，形成情景、反证和条件式建议
        ↓
核验关键数字与引用，显示速读和完整报告
        ↓
版本化保存，下一次研究显示相对上次的变化
```

### 1. 先把研究对象对准

固定品种、交易所、具体合约、行情截止时间和研究生成时间。燃料油 FU 与低硫燃料油 LU 不混用；主力连续图与具体合约用于不同问题，明确标注。

当前研究可以使用最新可得资料，但分别列出不同数据的日期。历史时点研究不得使用当时尚未公布的信息。行情明显滞后时，不给以旧价为基础的“当前入场建议”。

### 2. 框架真的负责决定查什么

沿用品种框架的指标编号，在项目内部补充“指标到数据源”的绑定，不擅自改只读技能包或交易规则。

每个指标声明：为何重要、取哪张表、更新频率、允许使用的替代指标、需要何种历史长度、缺失会影响哪项判断。不同品种有不同必查清单，不把股指、国债、工业品、农产品套进同一套供需模板。

### 3. 搜索、原文和数据各司其职

- 官方接口或统计表优先取得价格、库存、产销等数值。
- 元宝搜索寻找最新政策、行业事件、官方发布和公开研报；检索按指标拆分，不只搜“燃料油最新消息”。
- 搜索返回标题、摘要或链接后，继续读取对应原文或原表。仅有摘要的内容标为线索，不作为关键数字的已核验证据。
- 研报保留作者、机构、发布日期和引用的原始数据源；研报建议归入观点，不转换成官方事实。
- 某来源失败时，在限定时间与调用预算内换备用来源。受限、超时、付费和没有公开数据分别列明，不全部归为“没有资料”。

### 4. 缺口驱动补查

例如库存未取得，就查该库存的原发布机构、对应期次和可信转载；不能因为已有“油价上涨”新闻就跳过库存。

同一条原始消息被十家转载，只算一个证据来源。来源间有冲突，先核对时期、地区、品级和修订记录；无法消除时并列呈现，暂停依赖它的结论。

关键缺口未补齐，仍交付已核实的部分，但状态显示“部分完成”，并明确哪些判断不能做。不得用篇幅或来源数量掩盖缺口。

### 5. 分析要解释传导，不堆材料

每条重要变化都要讲明：发生了什么 → 影响供需或成本的哪个环节 → 影响哪个市场与期限 → 还有什么抵消因素 → 用什么指标继续验证。

价格走势可作为环境证据，但火筛出的多头不能预先决定水必须看多。水需要主动寻找相反解释，并可以给出“技术偏多，但现有基本面不支持追涨”的独立判断。

贝叶斯思维用于比较解释和随证据更新，不重复计算同源证据。第一版优先显示“支持增强、支持减弱、证据分歧”，不生成“胜率 80%”之类未经校准的数值。确需主观概率时，必须同时说明主观性质、适用期限和假设，不混同交易胜率。

## 四、水页面应呈现什么

保留已经认可的低亮度蓝色背景、清晰文字和现有导航。此次核心是报告内容与阅读顺序，不重新做视觉主题。

### 第一层：一屏速读

默认进入这一层，约 400 至 700 字是写作目标，不靠省略关键风险凑字数。

| 区域 | 交付内容 |
| --- | --- |
| 研究身份 | 品种、具体合约、价格日期、研究时间、完成状态 |
| 一句话判断 | 当前主要矛盾和倾向，使用大白话 |
| 支持与反对 | 最重要的多头理由、空头理由，各自证据强弱 |
| 是否已反映 | 价格、基差与库存等是否共同验证；不能证明就写未知 |
| 专业建议 | 当前更值得关注什么、宜等待什么、最大风险是什么 |
| 改变判断的条件 | 可观察的指标与方向，不捏造触发阈值 |
| 数据提醒 | 哪些重要数据陈旧、缺失或相互矛盾 |

### 第二层：完整报告

使用连续正文与轻量目录，不把所有章节塞进多层卡片。

1. 品种定价地图：谁生产、谁消费、影响价格的关键环节。
2. 供需与库存：最新数值、环比同比、季节性、地区与库存类型区别。
3. 价格与估值：现货、具体期货、基差、近远月价差、成本利润或裂解价差。
4. 消息与政策：事件发生时间、新旧程度、真实影响规模、传导时滞。
5. 历史对照：当前在可比历史中的位置，相似案例的相同与不同之处。
6. 情景与建议：基准、偏强、偏弱情景，未来几个交易日与未来几周分开。
7. 原始证据与缺口：逐条来源、数据表、重要矛盾、下一次应更新的指标。

报告末尾保留“我的判断 / 本人四问”，默认不要求填写。新报告独立保存，用户选择应用草稿时才进入既有人工记录流程；检测冲突，不能覆盖新写的笔记。

下一次点击可优先更新已过期指标与新增事件，并显示“相对上次改变了什么”。本方案不擅自增加后台定时抓取或通知。

### 进度与等待

按钮启动后显示真实阶段：确认合约、采集证据、核对缺口、生成报告、校验完成。保留上次报告并明确日期，避免等待时只看见空白。

有足够证据时先显示初步速读，并标明仍在补查；完整报告稍后更新。取消“一定半分钟完成”的承诺。首次研究、缓存更新、网络受限三种情况分别测量耗时，再决定可承诺的时间。

## 五、燃料油作为第一份样板

现有 `FU.md` 已列出炼厂重质供给、船燃及发电需求、新加坡库存、高硫裂解价差；但自述仍为“研究规格待数据绑定与专业复核”。第一步是把这些要求接到实际资料，不宣布框架文件存在就算完成。

| 研究问题 | 拟获取与比较的内容 | 必须守住的口径 |
| --- | --- | --- |
| 最近为什么涨跌 | 具体合约日线、期限结构、原油环境、成交与持仓 | 收盘和结算分开；主力换月不制造涨跌 |
| 供应在收缩还是增加 | 炼厂加工、重质燃料供给、进出口和运输扰动 | 原油产量不能直接当燃料油供应 |
| 需求有没有兑现 | 按燃料类型拆分的船燃销量，发电与炼厂进料需求证据 | 船燃总量不等于高硫燃料油销量 |
| 库存是否真正紧张 | 新加坡相关库存、国内可得库存、交易所仓单及各自变化 | 地域、库存类型、单位与统计样本分列；仓单不等于社会库存 |
| 现货是否比期货更强 | 可比现货报价、FU 合约、基差与进口相关成本 | 品级、硫含量、地点、时间、币种、税运口径必须一致或有明确可复算调整 |
| 强弱是否只是原油带动 | 高硫燃料油相对原油的裂解价差及历史 | 币种、桶吨转换和品级依据可追溯，不直接相减不同单位价格 |
| 市场在交易什么预期 | 近远月结构、已发生事件与未来催化 | 近月减远月固定定义；不能把月差叫现货升贴水 |
| 现在在历史什么位置 | 可比序列的季节性、区间或分位、代表性阶段 | 使用真实样本区间和数量；不足不画假历史，不把季节性当必然规律 |

固定基差定义为“可比现货价 - 指定期货价”。正值解释为该现货相对该期货升水，负值解释为贴水，必须标明比较对象。“外盘现货升贴水”和“期货近远月价差”另列。

未来走势以条件情景表达。例如“若库存继续下降且现货走强，供应趋紧解释得到更多支持”；这是输出方式示例，不代表目前燃料油已满足条件。

### 已核实的数据入口与尚未验证的部分

- 新加坡海事及港务管理局（MPA）公开提供船燃月度统计；[官方说明](https://www.mpa.gov.sg/port-marine-ops/marine-services/bunkering/bunkering-statistics)与[政府数据目录](https://data.gov.sg/collections/388/view)已经读到，适合用作需求数据候选。
- 本次对上述目录公开展示的元数据 API 进行了只读调用，返回成功并包含两个子数据集编号。这仅验证入口可达，不等于最新数据和全部历史已经接入。
- 一个真实注意点：目录页面标注覆盖到 2026-08，但本次集合元数据的 `coverageEnd` 返回 2023-04。后续必须读取具体子数据集的实际观察日期，不能拿页面更新时间代替数据日期。
- [Enterprise Singapore StatLink](https://statlink.enterprisesg.gov.sg/)存在油品统计入口与登录说明；本次没有取得可直接用于自动化的库存历史原表，不承诺已打通。
- 商业现货价格、精细库存和完整历史序列可能需要授权。先验证合法可用的公开替代；不等价替代只标为代理，不伪装成目标指标。确需付费时才提交数据项、用途、费用与缺失影响供用户一次决定。

## 六、真实性和时效性怎样落地

每条重要证据至少保存：

| 类型 | 必要字段 |
| --- | --- |
| 身份 | 证据编号、指标编号、品种/合约、事实/观点/推断 |
| 时间 | 数据所属期、原文发布时间、采集时间、研究截止时点 |
| 口径 | 原表名称、地域、品级、单位、币种、含税与运费、库存或流量 |
| 来源 | 发布者、原始链接、页码或表格定位、原始来源组、合法可保存的摘录或快照 |
| 状态 | 已核实、仅线索、过期、冲突、不可得、需授权 |
| 派生计算 | 输入证据、公式、换算依据、可比区间与修订版本 |

时效按发布频率判断。昨天重新转载的旧数据不等于新数据；最新可得月报可以有用，但不能冒充今日库存。后续修订保留版本，不回写覆盖旧报告的证据。

报告的每个重要数值与事实判断都连接到具体证据，不只在末尾放一串首页链接。推断要写清“由哪些事实推得，仍有哪些其他解释”。

确定性检查负责日期、单位、数值、计算、链接和证据编号；模型复核负责逐条比较论断和原文、找反证。模型复核本身仍可能出错，不标为“保证真实”。关键矛盾未解决时降级相应结论。

输入的网页、PDF 和搜索结果均视为资料，不允许其中的文字改变任务指令、索取凭据或执行操作。外链提取还需限制内网访问、跳转、文件大小与格式，防止原文抓取成为安全入口。

## 七、元宝搜索如何接入

建议把它作为现有采证模块中的一个可替换搜索来源，不作为唯一数据源，也不要求切换为元宝聊天产品。

已核对腾讯云[产品页](https://cloud.tencent.com/product/wsa)、[标准接入指南](https://cloud.tencent.com/document/product/1806/121802)和[计费说明](https://cloud.tencent.com/document/product/1806/121798)。官方支持返回结构化搜索结果，标准接入使用云端鉴权；它解决资料发现，不代替原文核验和专业统计数据。

截至本次查看，计费页列示极速版 14 元/千次、标准版 20 元/千次、旗舰版 26 元/千次，旗舰版仅限企业用户。可先用标准版做相关性测试，不因名称直接购买高版本。页面也说明超出资源包可能转为后付费，需要应用侧限额。

用户提到的 6000 次活动额度与日常 2000 次额度，本次尚未在已读取的官方活动规则及本人控制台中完成确认，不据此承诺免费使用。账户是否开通、实际剩余额度和模型余额均未核验。

实施时：

- 优先核实可用的服务专用凭据；否则使用最小权限的标准云 API 凭据。凭据只在本地服务端安全保存，不放网页、源码、报告或聊天。
- 设置每份报告与每日调用预算，超过预算停止继续付费请求并显示缺口。免费额度未确认时，不把额度猜成已生效。
- 只传研究品种、公开问题和必要公开证据；不将账户余额、持仓、完整个人资料库自动发送给搜索服务。
- 搜索费用、模型费用和商业数据授权分开显示，避免将“搜索免费”误认为“整个研究免费”。
- 对相同查询合理缓存，日、周、月数据按各自发布时间更新；重试也计入预算，不无限搜索。
- 开通、实名验证或确有付费选择时才需要用户介入；查材料、写查询、解析和排错由小木完成。

这是小木自己的后台能力，不能依赖当前 Codex 聊天临时替它联网；还必须验证桌面程序重启后仍能独立运行。

## 八、实施顺序与验收

| 阶段 | 工作 | 必须看到的成果 |
| --- | --- | --- |
| 1. 保护现状 | 备份当前代码、报告、业务库和配置；敏感凭据不进入普通报告包 | 原卡片、人工笔记、批准记录、规则和余额有可核对快照 |
| 2. 打通燃料油证据 | 将 FU 指标绑定到具体来源；接搜索适配器、原文读取与逐项补查 | 每个必查项有证据或明确缺口，重要数值能追到原表 |
| 3. 生成专家式报告 | 输出事实表、主矛盾、历史对照、情景、条件建议和反证 | 不靠四维新闻摘要替代供需；遇到关键缺口不强行定论 |
| 4. 改水页面 | 一屏速读、完整报告目录、证据展开、真实进度、上次变化、个人记录 | 用户无需填表，点击一次能阅读；旧报告与笔记不被覆盖 |
| 5. 扩到其他品种 | 复用共同流程，逐类核实各品种指标与数据绑定 | 不能以“已支持品种数量”替代逐品种覆盖；不足的品种明确标注 |

代码重点落在已有 `research-agent.mjs`、`research-evidence.mjs`、`research-audit.mjs` 与水页；原有价格上下文、任务存储、草稿应用和人工冲突保护继续复用。新适配文件只服务必要的数据来源，不为此重构整个工作台。

### 验收用真实任务和相邻反例

1. 正常燃料油研究：关键数字逐项对原始依据抽查，核心指标逐项盘点，不只数来源条数。
2. FU 与 LU、具体合约与主力切换：不混数据，不因换月制造变化。
3. 陈旧月报、今天转载的旧报告、同源多次转载：日期和来源去重正确。
4. 缺现货、库存冲突、单位不齐：不计算伪基差，不输出虚构历史分位。
5. 搜索超时、额度用尽、模型不可用：显示已取得部分与剩余障碍，不报“全部完成”。
6. 同一品种重复点击、取消、进程重启：避免重复计费任务，能够查看或恢复已存结果。
7. 人工笔记在研究期间被修改：不能被 AI 草稿静默覆盖。
8. 桌面真实操作：从火进入水、点击研究、阅读速读与原文、再看旧报告，功能实际可用。
9. 规则与记录保护：前后核对业务表、交易规则及已有批准状态，未新增下单或自动批准行为。

对正常完成、部分完成、失败分别验收。单元测试通过不能替代报告事实核对；一份燃料油样板通过也不等于其他品种都已达到同等质量。

## 九、本轮结论

最合适的升级不是继续加输入框，也不是仅换一个搜索引擎，而是把现有“新闻摘要加阶段判断”推进到“品种指标驱动的采证、核验和专家式解释”。

先用燃料油做完整样板：用户只点一次，看到主线、依据、分歧、风险和条件建议。达到这一实际效果后，再按品种定价机制扩展。

本轮完成了代码和样例检查、外部官方文档核对、一个公开数据元信息入口的只读试取，以及本方案。尚未开通元宝、调用付费模型生成新版报告、修改水页面或进行新版运行验收。下一步实施的依据是本方案，不是把这些未完成事项算作已经交付。
