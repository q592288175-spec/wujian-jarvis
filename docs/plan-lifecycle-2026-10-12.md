# 计划移除、交接与旧轮次检查

日期：2026-10-12，北京时间。仅修改十月小木项目。

## 旧轮次差异是什么

“系统运行轮次”保存当轮使用的规则正文和程序哈希，不等于单个品种的交易轮次。旧运行 `90276353-b76c-47be-b875-de115c545e36` 从 2026-10-10 开始锁定。本次修改前逐文件比较发现三项差异：

1. `scripts/fire_scan.py`：已存在的文华具体主力映射适配，与旧运行快照不同。
2. `integrations/five-workbench.mjs`：多账户、余额同步及账户隔离改造。
3. `integrations/trade-ledger.mjs`：余额分表接入、避免重复接入余额、北京时间记录。

原来按整份文件计算哈希，账户程序升级也会提示差异。但本次同时存在主力映射变动，不能视为纯界面变化直接放行。诊断保存在 `output/plan-lifecycle/lock-diff`，没有替换旧快照或恢复旧代码。

差异会阻止冻结和批准新计划，也会阻止受锁定保护的火刷新；不会阻止如实记录成交、保护和退出。本次保留这项既有保护，不修改规则、主力映射、筛选或风险阈值。

金页现在显示差异文件及“核对旧轮次”入口，直接进入木。正确处理顺序：先由本人核对各账户实际持仓和委托，取消不再执行的计划；确认本轮风险已结清、事项已处理，再在木填写结果并结束旧轮次。下次提交计划自动锁定当前文件。旧运行快照、历史计划、原交易轮次和冻结预算继续保留。

正式库中的烧碱旧计划有批准历史，但没有执行记录。本机无执行记录不能证明交易软件无持仓，因此未擅自取消该卡、释放其预留或结束旧运行。是否只是测试且无真实持仓/委托，等待本人确认。

## 水、金、土统一移除

- 每个品种右侧统一使用叉号，提示“移除并归档”。
- 确认窗显示关联计划、执行、复盘数量，要求选择原因并确认交易软件中无持仓、无未撤委托。
- 确认后同一卡从水、金、土当前队列一起移除；关联记录保留，不物理删除。
- 未执行的计划改为“已取消”；本人已核对的未成交预留同时释放，取消前状态和原因写入操作审计。
- 有实际持仓、历史成交待对账、未确认委托或待办异常时拒绝移除，说明需要处理的事项。不发送券商撤单。
- “已移除记录”按当前账户查询，可查看全部历史、恢复观察。
- 恢复保留账户、合约、方向、交易轮次、亏损及原预算，不恢复旧批准。火再次添加同一已归档候选时先提示恢复，避免直接重开卡重置预算。
- 归档后补录真实成交时重新显示该卡，并按原逻辑记录异常；失败事务不改变归档状态。

## 金的简化流程

填写条件 → 自动显示以损定量 → “下一步：交给土执行” → 核对摘要 → “确认，交给土执行”。

- 去掉单独的“以损定量”按钮，保留原公式和实时计算数值。
- 原“冻结新版本”是保存不可覆盖的计划快照；原“人工批准”是本人确认当前版本和风险。现在两个后台步骤由一个前台流程串联，审计仍分别保留。
- 点击下一步会保存待确认版本并执行原风险检查；确认窗显示账户、具体合约、方向、入场/止损、最终手数、计划风险及退出规则。
- 返回修改不会批准；同一表单未变化的再次确认不重复建版本。
- 金额、环境、计划版本或其他卡占用风险变化后，旧确认失效，必须重新核对。
- 检查失败留在金并显示原因，不导航到土；输入不清空。已经批准且表单未改时按钮为“前往土·执行管理”。
- 确认只是交接计划，仍须本人在交易软件执行；没有新增下单或券商连接。
